1. Objetivo

Nos últimos tutoriais foram apresentadas as formas básicas de uso da ferramenta Ftrace, sendo essa acessada diretamente pelo sistema de arquivos debugfs/tracefs. Apesar da interface provida pelo debugfs ser simples, em alguns casos essa pode ser inconveniente. trace-cmd é uma ferramenta de linha de comando em espaço de usuário que serve como interface de alto nível para o Ftrace. Nesse tutorial iremos instalar essa ferramenta e usá-la juntamente com a ferramenta gráfica KernelShark para realizar depuração visual do kernel.

2. Instalando a ferramenta trace-cmd

No diretório do buildroot, execute make menuconfig e selecione o pacote trace-cmd:

Target packages  --->
    Debugging, profiling and benchmark  --->
         [*] trace-cmd

3. Uso da ferramenta trace-cmd

$ trace-cmd record -e ext4 ls
$ trace-cmd report

3.1. Filtrando apenas uma única função

$ trace-cmd record -p function -l __do_page_fault
$ trace-cmd report

3.2. Filtrando um único processo

$ trace-cmd record -p function -P <PID>
$ trace-cmd report

3.3. Usando o modo function_graph

$ trace-cmd record -p function_graph -P <PID>
$ trace-cmd report | head -50

3.4. Monitorando eventos

$ trace-cmd record -e sched:sched_switch
$ trace-cmd report

3.5. Aplicando filtros

$ trace-cmd record -p function_graph -l do_IRQ -e irq_handler_entry sleep 10
$ trace-cmd report

4. Visualização de traces

4.1. Exportando o trace para a máquina host (via mount tradicional)

$ sudo mount output/images/rootfs.ext2 /media/cdrom
$ sudo cp /media/cdrom/root/trace.dat .
$ sudo umount /media/cdrom

4.2. Realizando o tracing pela rede

# No Host:
$ trace-cmd listen -p 12345 -D -d ./tracing -l ./tracing/logfile

# No Guest (QEMU):
$ trace-cmd record -N 192.168.1.1:12345 -e sched_switch -e sched_wakeup -e irq ls

4.3. Exportando direto no Codespace via e2tools (Powered by Aluno Bernardo)

No Codespace, copie arquivos do filesystem ext2 sem privilégios de loop mount:

$ sudo apt-get update && sudo apt-get install e2tools -y
$ e2cp output/images/rootfs.ext2:/root/trace.dat trace.dat

5. KernelShark no Codespace

Instale o KernelShark no host e abra a interface gráfica:

$ sudo apt-get install -y kernelshark
$ kernelshark trace.dat

Para abrir direto no navegador dentro do Codespace:

$ curl -fsSL https://gist.githubusercontent.com/miguelxvr/3c123ef67611652af9d2e45eccb8fc0a/raw/ | bash -s -- start

6. Atividade 1

Visualizar o comportamento da chamada de sistema em uma aplicação exemplo (ex: syscall_test) utilizando trace-cmd e KernelShark: 

# No Guest (QEMU):
$ trace-cmd record -p function_graph -l sys_listProcessInfo -l sys_listSleepProcesses -l sys_printMessage syscall_test
# ou gravar todos os eventos de chamadas de sistema:
$ trace-cmd record -e raw_syscalls:sys_enter -e raw_syscalls:sys_exit syscall_test

7. Atividade 2

Aplicação multi-thread concorrente para análise de escalonamento via trace-cmd record -e sched_switch e KernelShark: 

#include <stdio.h>
#include <pthread.h>
#include <semaphore.h>

#define THREADS		5

void *task(void *arg){
	int tid;

	tid = (int)(long int)arg;

	while(1){
		putchar('a' + tid);
	}
}

int main(void){
	long int i;
	pthread_t threads[THREADS];

	for(i = 0; i < THREADS; i++)
		pthread_create(&threads[i], NULL, task, (void *)i);

	pthread_exit(NULL);

	return 0;
}
